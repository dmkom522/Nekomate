## 如何解读测试

本项目区分下列证据，不把它们混为“AI 已经理解整段课程”。

| 检查 | 能证明 | 不能证明 |
| --- | --- | --- |
| 核心单元测试 | 时间 / 格式校验、缓存淘汰和上下文组织符合测试用例 | 操作系统能采到窗口 |
| 本地 HTTP 传输测试 | 图片、历史、认证头、multipart 音频确实发往测试服务 | 外部服务支持这些字段或能理解课程 |
| 桌面合成输入集成测试 | 界面、IPC、真实图片编码、不同画面进入请求、保存与恢复 | 真实窗口 / 系统音频捕获正常 |
| 真实窗口夹具测试 | 自建测试窗口的不同画面进入缓存 | 所有视频网站兼容、受保护视频可录制 |
| 真实 API + 课程验证 | 指定模型在指定问题上的效果 | 全部模型或全部课程效果 |

目前没有内置真实 API Key。真实模型对 B站 18.06 的答疑质量需要使用者配置服务后验证，不能由模拟服务的回答代替。

建议真实验收：先在 18.06 找一个必须结合前面板书才能回答的问题，播放一段并提问；检查发送的画面能否覆盖前后变化、公式是否清晰、回答引用是否正确、是否遗漏必要前提。再测试暂停、跳转、倍速、最小化和关闭源窗口。

音频验收应使用可辨识的语音片段，检查转写文本及区间。仅看到音轨或成功收到 HTTP 回包不能证明采到了老师的声音。

导出记录包含抽样时间和变化统计。它们不等于视频总帧数、源帧率或有效帧率，本产品不宣称提高源视频帧率。
